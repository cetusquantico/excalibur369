# Reporting a problem

For a normal correctness issue, open an issue with a synthetic or solved public
fixture, the command, expected behavior, CPU information and compiler version.

For a suspected security issue, use GitHub private vulnerability reporting if the
repository owner has enabled it. Otherwise request a private contact from the
maintainer without posting sensitive details publicly. Never attach wallet seeds,
unpublished private keys, credentials, or personal checkpoints.

Checkpoint integrity checks detect accidental corruption; they do not authenticate
a file from someone else. Keep each checkpoint under one running process. The
supported purpose is participation in intentionally public Bitcoin puzzles.
